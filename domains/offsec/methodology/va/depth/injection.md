# Injection 심층 분석 (A4 Depth)

> A4 입출력 경계에서 인젝션 후보가 발견되었을 때
> 유형별 심층 질문으로 정밀도를 높입니다.

---

## 적용 조건

```yaml
Trigger: "Phase 1 A4에서 쿼리 구성/명령 실행/템플릿 렌더링/객체 복원/스키마 쿼리에 외부 입력 사용이 감지된 경우"
```

## 핵심 원칙

```yaml
Universal_Principle: |
  "사용자 제어 데이터가 코드/쿼리/명령/템플릿/객체 구조의 의미를 변경할 수 있는
   모든 경로가 인젝션 후보이다. 기술(SQL, NoSQL, LDAP, GraphQL, 템플릿, 직렬화)이
   달라도 원칙은 동일하다 — 데이터와 제어 구조의 혼합이 근본 원인."
```

## SQL / ORM Injection

```yaml
심층_질문:
  - "파라미터 바인딩(prepared statement)이 아닌 문자열 연결로 쿼리를 구성하는가?"
  - "ORM을 사용하더라도 raw query, literal, knex.raw 같은 이스케이프 탈출 경로가 있는가?"
  - "WHERE 절뿐 아니라 ORDER BY, LIMIT, 테이블명, 컬럼명에도 사용자 입력이 들어가는가?"
  - "IN 절에서 배열을 직접 삽입하는가? (바인딩이 배열을 지원하지 않는 드라이버)"
  - "stored procedure 호출 시 프로시저 내부에서 동적 쿼리를 구성하는가?"

놓치기_쉬운:
  2차_인젝션: |
    사용자 입력 → DB 저장(이스케이프됨) → 다른 쿼리에서 읽기 → 새 쿼리 구성에 사용.
    첫 저장은 안전하지만 두 번째 사용에서 인젝션 발생.
  배치_인젝션: |
    배치 작업/크론에서 DB 값을 읽어 동적 쿼리 구성.
    사용자 요청 컨텍스트가 아니라 감지가 어려움.
```

## NoSQL 연산자 주입

```yaml
원칙: "쿼리 객체를 사용자 입력으로 구성하면, 연산자($gt, $ne, $where 등)가 주입될 수 있다."

심층_질문:
  - "req.body/req.query를 그대로 쿼리 조건에 전달하는가? (객체 통째로 전달 패턴)"
  - "쿼리 연산자가 사용자 입력에서 유입될 수 있는가?"
  - "key-level injection이 가능한가? (Express 쿼리 파싱이 객체를 만드는 경우)"
  - "$where, $expr 같은 JS 실행 연산자에 사용자 입력이 도달하는가?"

놓치기_쉬운:
  - "MongoDB: strictQuery가 false면 임의 필드 추가 가능"
  - "DynamoDB: FilterExpression이 문자열 연결로 구성되는 패턴"
  - "Redis: EVAL/EVALSHA에 사용자 입력이 스크립트 본문으로 유입"
```

## LDAP Filter/DN 주입

```yaml
원칙: "LDAP 필터나 DN을 사용자 입력으로 구성하면, 필터 논리를 변조하거나 DN을 탈취할 수 있다."

심층_질문:
  - "사용자 입력이 LDAP bind DN 또는 search filter 문자열에 직접 포함되는가?"
  - "RFC 4515 특수문자 escape가 올바르게 적용되는가?"
  - "인증 성공 판정 로직이 엔트리 존재만 확인하는가, 속성 매칭까지 하는가?"
  - "anonymous bind가 활성화된 서버에서 구조 열거 가능한가?"
```

## Command Injection

```yaml
심층_질문:
  - "OS 명령을 구성할 때 사용자 입력이 인자에 포함되는가?"
  - "shell=true 또는 동등한 옵션으로 셸 해석이 활성화되어 있는가?"
  - "allowlist 기반 검증인가, blocklist(특수문자 필터) 기반인가?"

놓치기_쉬운:
  간접_명령: "사용자 입력 → 파일명 생성 → 해당 파일을 다른 명령의 인자로 사용"
  환경변수_주입: "사용자 입력이 환경변수 값으로 설정되고 셸 명령에서 참조"
```

## Template Injection (SSTI)

```yaml
원칙: "사용자 입력이 템플릿 변수가 아닌 템플릿 문자열 자체에 유입되면 코드 실행이 가능하다."

심층_질문:
  - "사용자 입력이 템플릿 문자열로 직접 전달되는가? (렌더링 파라미터가 아닌 템플릿 자체)"
  - "템플릿 엔진의 sandbox/restricted 모드가 활성화되어 있는가?"
  - "이메일/리포트/admin 콘솔 등 '템플릿 편집 기능'이 인증·인가되어 있는가?"
  - "sandbox 우회 gadget이 존재하는가?"
```

## API 쿼리 언어 남용 (GraphQL 등)

```yaml
원칙: "쿼리 언어가 클라이언트에 노출되면, 구조 탐색/복잡도 공격/인가 우회의 공격면이 된다."

심층_질문:
  - "Introspection이 프로덕션에서 enabled인가?"
  - "쿼리 복잡도/깊이 제한이 있는가?"
  - "쿼리 배칭과 alias 스태킹에 제한이 있는가?"
  - "인가가 resolver 수준에서 field-by-field 검증되는가, schema 수준만인가?"
  - "mutation이 GET 요청으로 실행 가능한가? (CSRF)"
```

## 객체 구조 오염 (Prototype Pollution 등)

```yaml
원칙: "신뢰할 수 없는 데이터를 기존 객체에 병합하면, 프로토타입 체인이나 내부 속성을 오염시켜 동작을 변조할 수 있다."

심층_질문:
  - "사용자 JSON을 Object.assign/lodash.merge/defaultsDeep 등으로 기존 객체에 병합하는가?"
  - "__proto__, constructor, prototype 키가 필터링되는가?"
  - "오염된 프로토타입이 템플릿 엔진/환경변수를 통해 RCE로 확대되는가?"
```

## 신뢰 경계를 넘는 객체 복원 (Deserialization)

```yaml
원칙: "외부 데이터에서 객체를 복원할 때, 타입/클래스를 제한하지 않으면 임의 코드 실행이 가능하다."

심층_질문:
  - "신뢰 불가 데이터를 역직렬화하는 코드가 있는가?"
  - "역직렬화 시 타입/클래스 제한(allowlist)이 있는가?"
  - "역직렬화 결과로 생성된 객체의 메서드가 자동 호출되는가? (toString, hashCode, __wakeup)"

놓치기_쉬운:
  다단계_직렬화: "JSON 내부에 Base64 인코딩된 직렬화 데이터가 중첩되어 추가 역직렬화"
  설정_파일_파싱: "YAML.load()가 기본적으로 임의 객체를 생성하는 경우 (Python, Ruby)"
  메시지_큐: "큐에서 수신한 메시지를 '내부 메시지이므로 신뢰'하고 역직렬화"
```

# 동시성 심층 분석 (A8 Depth)

> 상태 읽기와 쓰기 사이에 다른 요청이 끼어들 수 있는
> 모든 경로를 분석하여 race condition과 상태 일관성을 점검합니다.

---

## 적용 조건

```yaml
Trigger: |
  Phase 1 A8에서 비즈니스 로직 상태 관리 이상이 감지된 경우, 또는
  결제/자산/재고/투표 등 상태 변경이 원자적이지 않은 패턴 발견 시
```

## 핵심 원칙

```yaml
Universal_Principle: |
  "상태를 읽고(check) 쓰는(use) 사이에 시간 간격이 있으면,
   그 간격에 다른 요청이 끼어들어 check 결과를 무효화할 수 있다.
   이것이 TOCTOU(Time-of-Check-to-Time-of-Use)의 근본 원인이다."
```

## Race Condition

```yaml
심층_질문:
  - "잔액 확인 → 차감이 원자적(atomic) 트랜잭션인가, 별도 쿼리인가?"
  - "재고 확인 → 주문 생성이 단일 트랜잭션에서 수행되는가?"
  - "쿠폰/코드 사용 확인 → 사용 처리가 원자적인가?"
  - "동시 요청으로 잔액/재고/쿠폰을 이중 소비할 수 있는가?"
  - "DB 수준 잠금(SELECT FOR UPDATE, 낙관적 잠금)이 적용되어 있는가?"

놓치기_쉬운:
  API_레벨_Race: |
    동일 사용자가 동시에 2개 요청을 보내 잔액을 이중 사용.
    각 요청은 개별적으로는 정상이지만, 동시 실행 시 무결성 위반.
  캐시_DB_불일치: |
    Redis 캐시 읽기 → 조건 충족 → DB 업데이트.
    캐시 읽기와 DB 업데이트 사이에 다른 요청이 캐시를 오염.
```

## 분산 시스템 동시성

```yaml
심층_질문:
  - "여러 서버 인스턴스가 동일 리소스에 동시 접근할 때 분산 잠금이 있는가?"
  - "메시지 큐 컨슈머가 동일 메시지를 중복 처리하지 않는가? (at-least-once + idempotency)"
  - "이벤트 소싱/CQRS 패턴에서 읽기 모델과 쓰기 모델의 최종 일관성 창이 악용 가능한가?"
```

## 파일시스템 TOCTOU

```yaml
심층_질문:
  - "파일 존재 확인 → 파일 읽기/쓰기 사이에 symlink 공격이 가능한가?"
  - "임시 파일 이름이 예측 가능한가?"
  - "공유 볼륨에서 여러 프로세스가 동일 파일에 접근하는가?"
```

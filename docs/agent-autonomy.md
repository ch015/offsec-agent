# OffSec 후속 탐색과 종료 원칙

현재 구현 기준: 2026-09-21. 앱 연결과 취소 사용법은 [코드 연동](embedding.md)을 참조한다.

v1/v2 SDK system prompt에 공통 행동 지침을 추가했다. 배정된 소스를 시작점으로 조사하고, 관측한 호출·import·권한 경계·데이터 흐름이 가설 판정에 영향을 줄 때만 추가 탐색한다. 준비된 의존성 목록 전체를 순서대로 읽거나 모든 작업 단위에서 저장소 전체를 다시 분석하지 않도록 지시한다.

작업 단위의 읽기 허용 목록을 기존 owned/context 파일에서 봉인된 source inventory의 정확한 파일 경로까지 확대했다. 각 단위의 `00_source_exploration.json`에 탐색 가능한 소스 경로를 제공한다. 새로운 소스는 근거가 있는 후속 탐색에만 사용한다. finding 소유권, 원래 담당 파일, 다른 단위의 보고서 차단, 파일 쓰기·네트워크·실환경 실행 권한은 기존 계약을 유지한다.

추가 소스 읽기는 도구 ledger에 남는다. 기존 scope assurance의 owned/context 집계는 원래 작업 계획에 대한 지표로 유지되므로 추가 탐색 파일 전체를 새 coverage로 주장하지 않는다. 관계의 관련성 판단과 불필요한 읽기 억제는 모델 지침이다. 기존 SDK 호출을 모두 의미적으로 분석해 자동 중복 차단하는 장치를 추가한 것은 아니다.

v2는 짧은 A1–A8 체크리스트와 단위별 증거 색인을 필수 시작점으로 사용한다. 상세 방법론과 AST/Semgrep
근거는 필요할 때 조회한다. 정적 분석 후보의 sanitizer·중간 경로를 보존하며, 후보가 없거나 parser가
실패한 파일을 안전하다고 간주하지 않는다. AST와 Semgrep 모두 봉인된 파일 목록 안에서 실행한다.

단위 analyzer는 실제 소스 인용으로 뒷받침되는 교차 단위 질문을 선택적으로 제출할 수 있다.
호스트는 파일 소유권·범위·인용 일치·중복·개수만 확인하고, 질문의 의미적 타당성은 모델이 판단한다.
모델이 제시한 영향도 순서로 기본 최대 3개를 선택해 root analyzer 한 라운드(최대 32턴)에서 해결한다.
새 전체 진단이나 재귀 후속 요청은 금지한다. 질문이 없거나 비활성화했거나 분석 예산이 소진되면
추가 세션 없이 review로 진행하며 보류/무효 요청 수를 기록한다. 출력 검증 재시도는 기존 계약을 따른다.

시간 한도를 넘긴 worker의 AbortController를 SDK까지 전달하고 이후 도구 호출을 거부한다. 늦게 반환된 결과는 phase 성공 산출물로 수락하지 않는다. timeout된 단위를 즉시 재시도하지 않아 이전 실행과 겹치는 조사를 막는다. 종료한 worker의 타이머도 정리한다. 기존 15분 단위 상한, 계약상 턴/동시성/수정 제한을 유지한다. 실행 제한이 없는 별도 호출에 새 시간 상한을 일괄 적용한 것은 아니다.

재시도마다 실제 남은 run 예산을 다시 계산한다. v2는 병렬 세션의 예산을 실행 전체 한도 안에서 사전 예약하고 사용량이 확인된 잔액만 다음 호출에 재사용한다. 사용량을 잃은 실패는 예약액 전체를 보수적으로 차감한다. v1에는 이 예약 처리를 추가하지 않았다. SDK가 완료된 호출의 사용량을 알리는 특성상 마지막 호출의 초과 청구까지 차단하는 절대 과금 상한은 아니다.

v2 기본 동시성은 2다. 실행 예산이 설정돼 있으면 초기/후속 analyze가 전체 예산의 70% 안에서
배분받고, review 이후 10%, evaluate 이후 5%를 남긴다. 이전 단계가 쓰지 않은 금액은 후속 단계에서
사용할 수 있다. 별도 기본 달러 예산을 자동 설정하지는 않는다.

v2는 작업 단위 분석을 항상 사용한다. `workUnitMode: off`는 무시하지 않고 실행 전에 거부한다. 일부 단위 실패 시 미검토 파일을 보고서에 명시해야 하며 결과 coverage와 CLI 종료 코드 2로 부분 분석을 표시한다. 증거/범위/발행 게이트 실패는 최종 보고서로 승격하지 않는다.

`coverage.complete`는 실행 완료이며 보안 분석의 완전성이 아니다. 담당 파일 읽기 수와 정적 분석 공백,
미해결 사항, 후속 질문 보류 수를 함께 기록한다. `semanticCoverage`는 `not-proven`으로 명시한다.

검증은 추가 소스가 읽기 목록에 포함되는지, 목록 밖 파일과 다른 단위 산출물이 차단되는지, 시간 초과 취소가 전달되는지, 재시도 예산이 차감되는지에 대한 로컬 테스트와 기존 v1/v2/벤더 회귀 검사로 수행한다. 실모델의 탐색 효율·판정 품질 향상을 수치로 주장하지 않는다.
